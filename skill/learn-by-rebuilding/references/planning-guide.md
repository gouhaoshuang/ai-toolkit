# 路线规划指南

首次接触参考项目、重新划定学习范围或建立文档骨架时阅读。续写已确认的课程时，只需回看相关约定，不重复完整规划。

## 1. 从真实项目中确定起点

通常只需要参考项目位置和学习项目位置。先从会话、当前工作区和已有文档获取信息；只有无法可靠确定时再问用户。学习目标未说明时，可以根据项目提出一个推荐目标，并说明假设。

探索围绕一条核心执行路径展开，按需阅读：

- 参考项目的说明、目录、依赖声明、关键入口和核心模块。
- 能说明行为的测试、最小示例及必要数据格式。
- 学习项目已有的源码、测试、配置、文档和未提交改动。

先建立足够支撑路线的认识，再深入当前要展开的部分，不要求一开始穷尽整个仓库。只提供远程项目时，通过可用的只读方式阅读原始源码和官方资料；无法访问的部分明确列为信息缺口，不虚构接口。

记录课程所依据的参考位置；能方便取得版本或提交号时一并记录。检查路径是否仍然有效。环境信息从当前项目和用户偏好获取，不把某台机器的解释器路径写进通用教学规范。

## 2. 划定第一阶段范围

先回答以下问题，再决定课数：

1. 用户最终要亲手做出什么，怎样证明完成？
2. 哪些机制必须自己实现，哪些工具可复用？
3. 当前已经有哪些能力，哪些只是文档中的规划？
4. 最小可运行路径是什么，它依赖哪些概念与接口？
5. 哪些复杂度适合留在主线完成后？

区分“理解核心机制的教学版”和“完整复刻参考项目”的工作量，提出推荐范围，由用户决定。精简实现时，说明保留的关键行为、暂缓的功能和由此产生的限制。

不要默认迁移参考项目全部依赖、抽象、命令行参数、部署方案或性能优化。例如，对照测试使用大型框架，不意味着手写实现也必须依赖它。

## 3. 给出一条有理由的推荐路线

先用短文说明推荐目标和拆课逻辑，再列课程表：

| 课次与主题 | 要解决的问题 | 新增能力 | 参考位置 | 验收证据 |
|---|---|---|---|---|

实际填写时，每行聚焦一个主要问题。验收证据要具体到可观察行为、预期数值、状态变化或可解释的实验结果，不只写“代码完成”。参考位置可以指向关键模块或函数，无需罗列该课所有文件。

路线通常从最小行为出发，逐步引入必要的调度、组合和真实场景验证；根据项目调整。先确保每个局部机制能解释，再观察整体运行效果。避免把“程序能运行”或“指标变好”当作所有底层机制正确的证据。

补充必要前置知识和可选扩展即可，不同时展开多套完整路线。语言基础较弱时，把必要语法安排到第一次实际使用的位置，不默认增加一套独立语言课程。

## 4. 等待确认，再建立文档

首次推荐路线的交付是方案，尚不批量生成详细课程或改动学习项目。明确请用户确认目标、范围和拆课方向；这是用户选择学习路线的步骤，不是每课重复的权限申请。

用户确认后，记录路线并建立需要的文档。用户只确认路线但未要求首课时，先完成文档骨架；要求开始某课时直接编写该课。已有确认继续有效，后续仅在范围发生实质变化时重新讨论。

## 5. 默认文档骨架

空白学习项目建议使用：

```text
docs/
├── README.md
├── 学习路线.md
└── tutorials/
    ├── README.md
    ├── 第00课-学习准备.md
    └── 第01课-具体主题.md
```

这是逐步演进的示意，不要求立即创建列出的所有课程。已有 `knowledge/`、不同命名或多层课程目录时，沿用可用结构，不为统一外观搬迁用户文档。

### docs/README.md

简要说明学习项目目的、参考项目位置、当前范围、用户与 Agent 的分工，以及路线和教程入口。记录已知的基础环境及必要运行约定，避免复制完整课程表。

默认采用现有合适环境。用户已有 conda `agent` 环境且希望沿用时直接沿用；不假设其他用户或机器也有这个环境。未检查的依赖写为待确认，不替用户安装。

### docs/学习路线.md

保存已确认的目标、第一阶段边界、拆课理由、参考实现对应关系，以及影响后续课程的接口和验证约定。后续范围调整时更新此处，不另建一份内容相同的规划文档。

### docs/tutorials/README.md

维护课程顺序、每课目标和简短状态。只链接已经存在的教程；计划课程保留纯文本标题即可。需要记录进度时，将以下事实分开：

- 文档是否已编写。
- 源码是否已实现，以及判断依据。
- 是否执行过验证，以及执行者和结果。

可用备注表达，避免为每次会话建立复杂台账。没有证据的项目写“未确认”，不把文档完成标记为实现完成。

### 按需补充

- 原理说明过长、会被多课复用时，再增加 `docs/knowledge/`。
- 架构复杂且确实需要独立说明时，再增加架构文档。
- 项目根 `AGENTS.md` 由用户明确要求时才创建或更新；文档骨架本身不授予该权限。

源码、测试、`examples/` 和工程配置的目标结构可以在文档中展示，但其实际创建仍交给用户。

## 6. 规划完成检查

- 路线由参考代码和学习项目现状支撑，新增能力的前置条件清楚。
- 第一阶段终点具体，范围适合手写学习，暂缓项不会阻断主线。
- 依赖按核心、测试、对照和演示用途区分。
- 课程验收能检查本课关键机制，而不只是最终演示效果。
- 方案与用户已确认的要求一致，文档没有暗示 Agent 已经实现或运行项目。

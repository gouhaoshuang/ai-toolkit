# 手写复现学习项目

帮助用户通过亲手实现理解参考项目。课程从学习项目的真实状态出发，每次增加一段可理解、可验证的能力。课程数量、技术栈和工程结构由项目决定。

## 根据当前请求选择工作方式

| 用户请求 | 工作方式 |
|---|---|
| 提供参考项目，询问怎么学习 | 读取 [路线规划指南](references/planning-guide.md)，只读探索后提出推荐路线，等待用户确认 |
| 确认路线，要求建立文档 | 按已确认的范围创建最小 `docs/` 骨架；只展开本次要求的课程 |
| “写第 N 课”“继续下一课” | 读取已确认的路线、相关教程及实际源码，再按 [教程写作指南](references/lesson-writing-guide.md) 编写 |
| “检查我的实现” | 只读检查代码与测试，给出问题位置、原因、手动修改片段和验证方法 |
| 修改某课或调整方向 | 围绕本次要求修改相关文档；实质改变学习范围时先说明建议，待确认后展开新方向 |

用户已有明确路线，或已经指定要写的课程时，沿用该范围，不重新要求确认整套计划。用户要求一次写多篇时可以照做，并检查各篇之间的接口和前置条件。

## 学习项目的协作边界

以下约定作用于正在学习和复现的项目，不扩展到无关任务。

- 默认用户编辑全部源码、测试、示例、Notebook 和工程配置，包括空文件、包初始化文件、依赖声明与自动生成文件。Agent 直接编辑教学文档，默认放在目标项目的 `docs/` 下，并执行只读探索。
- 教程中的“创建文件”“修改函数”“运行测试”是交给用户执行的步骤。写出这些步骤，不代表对应文件已经创建或操作已经执行。
- “实现这一课”“修复这里”“继续”在此学习场景中默认指提供教程或修改指导。用户明确要求 Agent 直接修改代码时，只修改其授权范围；已有持续授权按原范围执行，单次授权不自动扩大为后续接管。
- 参考项目只作只读资料。发现问题时说明与学习目标的关系，不顺手改动参考项目或用户已有代码。
- 不因加载技能自动运行项目或测试、安装升级依赖、启动服务、训练或操作设备。按项目约定和会话已有授权判断；缺少授权时，在文档中提供用户可执行的步骤。
- 可以在项目约定允许时做不执行项目代码的语法、链接检查，或无文件写入的内存计算；避免产生字节码、缓存和输出文件。没有实际运行的检查不能记为通过。
- 读取并遵守适用的项目约定；用户明确要求时才更新 `AGENTS.md`，不通过改写约定扩大权限。

## 每次续写前恢复上下文

1. 确认参考项目、学习项目的真实路径，读取适用的 `AGENTS.md`、文档入口和已确认路线。路径失效时先在已知工作区定位，不沿用旧路径猜测文件内容。
2. 阅读与本课相关的当前源码、测试、配置和前一课。教程存在、文件存在、用户说完成了，都要与可获得的实现和验证证据分别看待。
3. 确认本课可依赖的接口、运行方式和前置知识。用户已写的配置和合理的实现选择优先沿用；不要让其为套用模板重做工程。
4. 如果缺少关键前置能力，给出具体缺口和最小补齐方法；不要用尚未实现的接口悄悄支撑下一课。只在缺失信息会实质影响方向或步骤时询问。

## 教学偏好

- 默认中文。先解释问题与设计，再分段手写；用具体输入和预期结果帮助理解。必要语法在首次使用时就地讲解，代码只加有帮助的简短注释。
- 每课形成一个小闭环：理解目标、手动实现、验证结果、解释原因。拆分依据是能力依赖与认知负担，不按参考仓库文件数平均分课。
- 测试简洁，覆盖关键行为和最容易写错的关系；不固定测试数量，不为每个小步骤增加一个测试函数。可重复的正确性检查优先进入测试，而不是反复给终端临时脚本。
- 演示和实验通常放在 `examples/`，不为一次教学实验扩充正式入口。正式入口本身是本课目标时可以讲解必要修改。
- 适合逐步观察数据、曲线或图像的实验可以用 `examples/*.ipynb`；普通命令行实验保留脚本。Notebook、辅助模块及其依赖都由用户创建或安装。
- 区分核心实现、测试工具、参考对照和可视化依赖。环境装有某个框架，不表示项目需要它；不使用成熟库替代本次要亲手学习的能力。

## 项目记忆与交付

通用方法留在本技能；具体路径、环境、范围、接口约定、课程路线和学习状态留在目标项目文档。不要把某次项目的绝对路径、课数、语言或依赖变成全局要求。

只同步本次相关的入口、路线和课程链接，保留用户已有补充。未编写的课程先用纯文本列出，避免建立无内容的占位教程或失效链接。

完成时简要说明改了哪些文档、下一步用户需要做什么、实际做了哪些检查。分别表达“文档已编写”“源码已实现”“验证已通过”；用户反馈通过与 Agent 实际执行通过也应注明来源。不把文档检查写成项目测试通过，不虚构运行结果。
